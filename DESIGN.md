# Design decisions

This file records *why* the project is built the way it is, including the dead ends.
Numbers quoted here come from `results/` (generated by `python -m dpt.run_all`) or from
the diagnostic runs described, which can be repeated with the code in `src/dpt`.

## 1. Device choice

| | NTH4L022N120M3S | NTH4L032N065M3S |
|---|---|---|
| Family | EliteSiC M3S, 1200 V, 22 mΩ typ. | EliteSiC M3S, 650 V, 32 mΩ typ. |
| Package | TO-247-4L (Kelvin source) | TO-247-4L (Kelvin source) |
| Why | Mainstream 800 V-bus part (EV chargers, solar, ESS); datasheet gives Eon/Eoff at 800 V / 40 A with the body diode as free-wheeler, i.e. exactly what a DPT reproduces | 400 V-bus counterpart; datasheet gives Eon/Eoff at 25 °C *and* 175 °C, so it would add a temperature validation point |
| Model | `onsemi_sicmosfet_1200m3s_ltspice`, v2.3 (Sep 2025) | `onsemi_sicmosfet_650m3s_ltspice`, v2.6 (Mar 2026) |

Both are current production parts with onsemi physical, scalable SPICE models
(TND6260). The 4-pin package matters: it allows the Kelvin-vs-non-Kelvin comparison
on one device.

**Outcome:** the 650 V model fails the dynamic sanity check in LTspice 26.0.1 (section 5),
so all switching results use the 1200 V part. The 650 V part stays in the code base with
its failed check visible, rather than being silently dropped.

## 2. Simulator: LTspice, not ngspice

The plan was ngspice (open source, runs in CI). It is not possible: onsemi ships the
models only vendor-encrypted. The PSpice library is Cadence-encrypted
(`$CDNENCSTART_ADV2`), the LTspice library is LTspice-encrypted. ngspice can run neither.
LTspice 26.0.1 (free, Windows/macOS) is therefore the simulator, driven in batch mode
(`LTspice.exe -b`) from Python. The binary `.raw` reader is written from scratch
(`dpt.rawread`) and unit-tested on synthetic files in both the LTspice (UTF-16 header,
float32 data) and ngspice (ASCII header, float64) dialects, so a later port to another
simulator only needs a new netlist dialect.

Consequence for CI: GitHub Actions runs lint and the unit tests (extraction, raw reader,
netlist generation, analysis), which need neither LTspice nor the models. The simulation
study is run locally and its outputs are committed.

## 3. Licensing of the models

The LTspice library header says: *"Permission is granted to use this file for simulations
but not to reverse engineer its contents."* That grants use, not redistribution, and the
onsemi site terms do not add a redistribution grant. The ZIPs are therefore gitignored.
`python -m dpt.fetch_models` verifies user-downloaded ZIPs against the SHA256 of the
versions used here (`third_party/onsemi/SHA256SUMS`). onsemi's download server rejects
non-browser clients (HTTP 403), so the script prints the exact product page and file name
instead of trying to work around that.

## 4. Circuit and test conditions

* **Topology**: classic half-bridge DPT, low-side DUT, high-side device of the same part
  number held off at −3 V through Rg,off as the free-wheeler. This matches the datasheet
  note "EON/EOFF result is with body diode". A generic recovery-free SiC Schottky option
  (`freewheel="sbd"`, not an onsemi model) exists only as a diagnostic.
* **Gate drive**: −3/+18 V (datasheet), ideal source with 5 ns edges on the measured edges,
  separate Rg,on/Rg,off via steering diodes when they differ. The *first*, zero-current
  turn-on uses a 50 ns edge: it is not measured, and the softer edge lets the solver start
  with a much smaller convergence aid (section 6).
* **Strays**: one external power-loop inductance `Lloop`, split half above the high side,
  half below the low side. Package inductances are inside the onsemi sub-circuit.
  Non-Kelvin mode adds `Lcs` between the power-source pin and the driver return.
* **Load**: 100 µH; first pulse `L·I/V − 60 ns` so the current at the moment vDS starts
  rising (not at the gate command) equals the target. The turn-off delay (~50 ns) would
  otherwise add ~2 A at 800 V / 20 µH. Switched currents are measured, not assumed.
* **DC link**: ideal source + 10 µF bulk, ramped from 0 V so the initial operating point
  is trivial.
* **Temperature**: the 4-pin models are isothermal and follow `.temp`; the static check
  reproduces the datasheet RDS(on) at 25 °C and 175 °C within 3 %.
* **Datasheet loop inductance is unknown**: onsemi does not publish its test-board
  stray inductance, and Eon depends strongly on it (a larger loop drops more voltage
  during di/dt). Validation is therefore shown over a 10–50 nH bracket; 30 nH, typical of
  a discrete TO-247 DPT board, is the nominal value for the sweeps.

## 5. Model sanity checks before trusting any switching result

`dpt.model_checks` runs two cheap tests per part:

1. RDS(on) from a DC operating point at the datasheet current, 25 °C and 175 °C.
2. Resistive-load turn-on: delay from gate edge to vDS = 50 %. A healthy model with an
   ideal driver and ~5 Ω switches in tens of ns.

The 1200 V model passes (19 ns). The 650 V model reproduces RDS(on) but takes **~600 ns**
to turn on. Its gate terminal reaches 18 V within 50 ns with zero gate current, yet the
channel stays off. The delay is unchanged with 0 V instead of −3 V off-bias, +22 V drive,
either source-pin assignment, the Normal or Alternate solver, and with or without the
convergence aid. It is not physical (datasheet td(on) = 8.8 ns), so the 650 V part is
excluded. This is an open item to report to the model contacts listed in the library
header. The likely cause is an incompatibility between the v2.6 library and LTspice 26.0.1,
but this has not been verified.

Another trap found here: the two libraries order the source pins differently (1200 V:
`D G S SS`; 650 V: `D G S1 S2` with S1 = driver source). The pin order is part of the
`Device` definition and covered by a unit test.

## 6. Convergence: the cshunt trap (the most important lesson of the project)

With default settings the 1200 V model does not converge in a DPT in LTspice 26.0.1, with
either solver. Alternate solver + `abstol=1e-7 vntol=1e-4` + `cshunt=1e-15` (1 fF from
every node to ground, a common LTspice trick) runs in ~20 s, and turn-off matched the
datasheet well. Turn-on, however, was 15× too slow and Eon about 5.5× the datasheet value.

What it was **not**: solver tolerances (reltol 1e-4, Gear integration: identical),
gate drive (a 0.1 Ω drive gave the same 0.4 A/ns), the body diode (same with an ideal
Schottky), pin order, or the 6-pin thermal variant. A resistive-load test switched
normally.

What it **was**: the convergence aid itself. The model has internal high-impedance nodes
(the failure messages name e.g. `nodeqdref`, `vrefppls`). A shunt capacitor on those
freezes internal state that the channel needs during clamped-inductive turn-on.
Sweeping cshunt shows it directly (`results/convergence.csv`):

| cshunt | Eon | current rise time |
|---|---|---|
| 1e-15 F | 2.71 mJ | 81 ns |
| 1e-17 F | 0.73 mJ | 11.6 ns |
| 1e-19 … 1e-22 F | 0.448–0.454 mJ | 5.4–5.8 ns |

(values from `results/convergence.csv`, nominal point; the investigation itself was done
on an earlier variant of the set-up with the same outcome.)

The default is 1e-21 F, on the converged plateau. Runs that fail retry at 1e-22, then
1e-19 F (`CSHUNT_LADDER`); the value that converged is written to every CSV row.
Lesson: **always sweep a convergence aid and show the results do not depend on it.**

## 7. Integration windows and definitions

Measured at the package terminals, as a real DPT would (`dpt.extract`):

| Quantity | Window / definition |
|---|---|
| Eoff | vGS falls through 90 % of its swing → iD falls through 2 % of the switched current |
| Eon | vGS rises through 10 % of its swing → vDS falls through 2 % of Vbus |
| Err | free-wheel current crosses zero towards reverse → reverse current < 2 % of Irrm; ∫ vDS,fw·iD,fw |
| dv/dt, di/dt | average slope between 20 % and 80 % |
| Overshoot | max vDS after turn-off minus Vbus; free-wheel peak vDS during DUT turn-on |
| Ringing | damped-sinusoid least-squares fit of vDS after the turn-off peak (frequency, ζ) |
| Gate bounce | max / min vGS of the free-wheeling device during DUT turn-on / turn-off |
| Switching times | both current-based (10/90 % iD) and voltage-based (10/90 % vDS) |

Gate-referenced start points follow IEC 60747-8/-9 practice. The delay phase carries
almost no power, so the energy hardly depends on the exact start point. All thresholds are
parameters (`Thresholds`) and are unit-tested on synthetic waveforms with analytic answers.

Caveats: terminal measurement cannot see the DUT's own Coss energy (dissipated inside the
die at turn-on), the same blind spot as a hardware DPT. Err/Qrr of a SiC body diode
include the free-wheeler's Coss charge, so they are not comparable with the datasheet's
Qrr, which is measured at 1 A/ns.

## 8. Engineering limits used in the analysis

* Every drain-source peak ≤ 80 % of V(BR)DSS (960 V for the 1200 V part): a common
  derating for cosmic-ray robustness and margin.
* |dv/dt| ≤ 50 V/ns, applied to the 1 ns peak slope (conservative): a typical EMI /
  motor-insulation guideline for SiC drives. The 20-80 % average is reported as well.
* Free-wheel gate excursion compared with VGS(th),min = 2.04 V (25 °C) and the −10 V
  absolute limit.

These are stated in `dpt/study.py` and can be changed in one place.
